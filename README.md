# AI Daily News

An automated, AI-powered daily news aggregator that fetches articles from RSS feeds and websites, enriches them with [Tavily](https://tavily.com) search, summarizes everything with any OpenAI-compatible LLM, and publishes a static site to **GitHub Pages** — entirely unattended.

## Features

- **Multi-source ingestion** — RSS/Atom feeds via [rss-parser](https://www.npmjs.com/package/rss-parser) and arbitrary website scraping via [cheerio](https://www.npmjs.com/package/cheerio).
- **Tavily-powered news search** — optional deep-web search per category using the [Tavily API](https://tavily.com), producing per-article TL;DRs and an aggregated "Daily Glance" summary.
- **Hierarchical AI summarization** — two-layer pipeline: individual article TL;DRs followed by a cross-category "Daily Glance" overview, all generated by any OpenAI-compatible model.
- **Any LLM provider** — works out of the box with OpenAI, Ollama, Groq, Together AI, vLLM, LiteLLM, or any provider exposing a `/v1/chat/completions` endpoint.
- **Markdown as single source of truth** — daily reports are generated as Markdown posts under `src/content/blog/` and rendered directly at build time via Astro's content collection — no intermediate JSON files.
- **Server-rendered news widget** — the `DailyNews.astro` component renders the latest Markdown report at build time with zero client-side JavaScript.
- **Blog archive** — all daily reports are browsable in the `/blog/` archive.
- **RSS output** — auto-generated RSS feed at `/rss.xml` via `@astrojs/rss`.
- **Sitemap** — auto-generated via `@astrojs/sitemap`.
- **Fully automated CI/CD** — two GitHub Actions workflows: one for daily generation + deploy (cron at 07:00 UTC), one for deploy-on-push to `main`.

## Architecture

```
Cron (GitHub Actions, daily 07:00 UTC) or push to main
  │
  ▼
scripts/generate-daily-report.ts
  ├── Read interests.json (categories + RSS feeds + websites)
  ├── Fetch RSS feeds via rss-parser
  ├── Scrape websites via fetch + cheerio
  ├── (Optional) Search via Tavily API → per-article TL;DRs → Daily Glance
  ├── Summarize articles via any OpenAI-compatible LLM
  └── Write Markdown → src/content/blog/YYYY-MM-DD-daily-report.md
  │
  ▼
astro build → Static HTML in dist/
  │         (DailyNews.astro renders the latest .md report at build time)
  ▼
GitHub Pages deployment (actions/deploy-pages)
```

## Tech Stack

- **Framework**: [Astro 6](https://astro.build) (static output) with MDX support
- **Language**: TypeScript (strict mode)
- **AI Summarization**: [OpenAI SDK](https://www.npmjs.com/package/openai) — compatible with any provider
- **News Search**: [Tavily](https://www.npmjs.com/package/@tavily/core) (optional)
- **RSS Parsing**: [rss-parser](https://www.npmjs.com/package/rss-parser)
- **Web Scraping**: [cheerio](https://www.npmjs.com/package/cheerio)
- **Image Processing**: [sharp](https://www.npmjs.com/package/sharp)
- **CI/CD**: GitHub Actions (cron + push + manual dispatch)
- **Hosting**: GitHub Pages

## Prerequisites

- **Node.js ≥ 22** (see `engines` in `package.json`)
- An API key for any OpenAI-compatible LLM provider
- *(Optional)* A [Tavily API key](https://tavily.com) for enhanced news search

## Configuration

### Interests (`interests.json`)

Edit `interests.json` to add or change categories, RSS feeds, and websites:

```json
{
  "llm": {
    "model": "gpt-4o-mini",
    "temperature": 0.4,
    "maxTokens": 4000
  },
  "maxArticlesPerFeed": 5,
  "categories": [
    {
      "name": "Your Category",
      "feeds": [
        "https://example.com/rss"
      ],
      "websites": [
        { "url": "https://example.com/blog", "title": "Example Blog" }
      ]
    }
  ]
}
```

Each category can have `feeds` (RSS/Atom), `websites` (arbitrary URLs), or both. Categories are also used as search queries for the Tavily pipeline when `TAVILY_API_KEY` is set.

### LLM Provider

The generation script uses the OpenAI SDK, which works with **any provider** that exposes a compatible `/v1/chat/completions` endpoint. Configure via environment variables:

- `LLM_API_KEY` or `OPENAI_API_KEY` *(required)* — API key. `LLM_API_KEY` takes precedence.
- `LLM_BASE_URL` *(optional)* — Base URL for non-OpenAI providers.
- `LLM_MODEL` *(optional)* — Override the model defined in `interests.json`.
- `TAVILY_API_KEY` *(optional)* — Enables the Tavily search pipeline for richer results.

**Provider examples:**

```bash
# OpenAI (default — no base URL needed)
OPENAI_API_KEY=sk-...

# Ollama (local)
LLM_BASE_URL=http://localhost:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=llama3

# Groq
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_API_KEY=gsk_...
LLM_MODEL=llama-3.3-70b-versatile

# Together AI
LLM_BASE_URL=https://api.together.xyz/v1
LLM_API_KEY=...
LLM_MODEL=meta-llama/Meta-Llama-3.1-8B-Instruct-Turbo
```

## Deploying to GitHub Pages

This project ships with two GitHub Actions workflows that handle deployment automatically. Follow the steps below to get your site live.

### 1. Configure `astro.config.mjs`

Set the `site` and `base` values to match your GitHub Pages URL. For a repo named `ai-daily-news` owned by user `octocat`:

```js
// astro.config.mjs
export default defineConfig({
  site: 'https://octocat.github.io',
  base: '/ai-daily-news',
  output: 'static',
  trailingSlash: 'always',
  integrations: [mdx(), sitemap()],
});
```

> **Why `base` matters:** GitHub project pages are served under `/<repo-name>/`. Without a matching `base`, all CSS, JS, and JSON asset paths will 404.

### 2. Push to GitHub

```bash
git remote add origin https://github.com/<YOUR_USERNAME>/ai-daily-news.git
git push -u origin main
```

### 3. Enable GitHub Pages

1. Go to your repository on GitHub.
2. Navigate to **Settings → Pages**.
3. Under **Build and deployment → Source**, select **GitHub Actions**.

### 4. Add Secrets and Variables

Go to **Settings → Secrets and variables → Actions** and add:

**Secrets** (required):
- `OPENAI_API_KEY` — your LLM provider API key (or use `LLM_API_KEY` if you prefer).
- `TAVILY_API_KEY` *(optional)* — enables the Tavily search pipeline.

**Variables** (optional):
- `LLM_BASE_URL` — base URL for non-OpenAI providers.
- `LLM_MODEL` — override the model from `interests.json`.

### 5. Understand the Workflows

The repository includes two workflows under `.github/workflows/`:

- **`daily-publish.yml`** — Runs on a cron schedule (daily at 07:00 UTC) or via manual dispatch. It generates the daily report, builds the Astro site, and deploys to GitHub Pages in a single job.
- **`deploy.yml`** — Triggered on every push to `main`. Builds and deploys the site without running the generation script (useful for design/code changes).

Both workflows use the official GitHub Pages actions (`actions/configure-pages`, `actions/upload-pages-artifact`, `actions/deploy-pages`).

### 6. Trigger Your First Deploy

Either push to `main` or go to **Actions → Daily AI News Publish → Run workflow** to trigger a manual run.

Once the workflow completes, your site will be live at:

```
https://<YOUR_USERNAME>.github.io/ai-daily-news/
```

### Troubleshooting GitHub Pages

- **Assets return 404** — Ensure `base` in `astro.config.mjs` matches your repository name (e.g., `/ai-daily-news`). This prefix is applied to all generated asset URLs.
- **Homepage shows "No report available"** — The `DailyNews.astro` component renders the latest Markdown post from the content collection at build time. Make sure `npm run generate` has been run at least once before building (the `daily-publish.yml` workflow handles this automatically).
- **Direct links to pages return 404** — Astro generates fully static HTML with `trailingSlash: 'always'`, so every route has its own `index.html`. This avoids the SPA routing issue entirely — no `404.html` hack or `HashRouter` is needed.
- **Jekyll interferes with underscored files** — The Astro build output in `dist/` may contain files starting with `_`. GitHub Pages runs Jekyll by default, which ignores these. The `actions/upload-pages-artifact` action includes a `.nojekyll` file automatically, so no manual action is required.
